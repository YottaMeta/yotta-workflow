# 元序路径模型

本文档解释 `SKILL.md`「〇、路径模型与状态目录判定」的实际用法，重点避免把项目根目录、源码目录和工作区根目录混为一谈。

## 1. 三个目录各管什么

| 名称 | 作用 | 判断要点 |
| --- | --- | --- |
| **项目根目录** | 拥有整个项目状态的目录；状态、任务、决策、路线图和交接锚点都以它为锚点 | `.workflow\` 放这里；可以没有 Git |
| **源码目录** | 存放代码、资源或某个仓库的目录；只是项目内部位置 | 可以位于项目根下；`.git` 不代表它一定是项目根 |
| **工作区根目录** | 并列存放多个项目根的父目录 | 它不拥有项目状态；不要在这里直接放 `.workflow` |

核心不变量：**状态跟着项目根走，不跟着源码仓库走。**

## 2. 定位算法

只认两种证据，按顺序执行：

1. **用户明确指定项目根**：用户直接说项目根是哪个目录，或交接锚点的“路径”指向该目录，直接使用。
2. **已有状态**：从 cwd 向上逐级查找 `.workflow\STATE.md`；找到最近的一份，其父目录就是项目根。沿用，不迁移、不复制。
3. **两种证据都没有**：停止初始化，只问一个问题——`这个任务的项目根目录是哪一个？`

不要用 `.git`、`package.json`、`src`、`README`、cwd 或目录结构自行猜项目根。目录里有源码只证明它是源码目录，不证明它拥有整个项目。

## 3. 典型形态

### 形态 A：用户明确说“当前目录就是项目根”

```text
my-app\                 # 项目根 = 源码目录
├── .git\
├── .workflow\
├── src\
└── package.json
```

项目根和源码目录重合；因为用户明确指定，状态放 `my-app\.workflow\`。

### 形态 B：用户指定上层目录为项目根

```text
my-project\             # 项目根；.workflow 放这里
├── .workflow\
├── AGENTS.md            # 项目级说明
├── app\                 # 源码目录；可以有独立 .git
│   └── .git\
└── web\                 # 另一个源码目录；也可以有 .git
    └── .git\
```

`app` 或 `web` 里有 `.git`，只说明它们是版本控制仓库，不说明它们拥有整个项目。项目根由用户指定，状态始终留在项目根。

### 形态 C：已有 `.workflow` 指出项目根

```text
D:\work\                # 工作区根；不要直接放 .workflow
├── project-a\          # 项目根
│   ├── .workflow\
│   └── src\
└── project-b\          # 另一个项目根
    ├── .workflow\
    └── app\
```

在 `project-a` 或 `project-b` 内工作时，向上找到最近的 `.workflow`，其父目录就是项目根；不能因为工作区根是 cwd 就在 `D:\work\.workflow\` 创建状态。

### 形态 D：从源码子目录开始会话，且已有项目状态

```text
my-project\             # 项目根
├── .workflow\
└── app\                # 当前 cwd
    └── .git\
```

从 `app` 启动会话时，先向上找到 `my-project\.workflow\`，直接沿用；不要因为 `app` 有 `.git` 就在 `app` 再建一份状态。

### 形态 E：没有任何定位证据

```text
unknown\                # cwd
└── src\
    └── .git\
```

此时不能因为 `src` 有 `.git` 就认定它是项目根，也不能因为 cwd 叫 `unknown` 就直接初始化。先问：`这个任务的项目根目录是哪一个？`

## 4. 防误判清单

- **不要**仅凭 `.git` 认定项目根。
- **不要**仅凭 `package.json`、`src\`、`README`、cwd 或源码目录名认定项目根。
- **不要**在工作区根直接初始化 `.workflow`。
- **不要**把已有 `.workflow` 从项目根搬到源码目录。
- **不要**在多个 `.git` 仓库嵌套时随便选一个仓库根当项目根；先看用户是否明确指定，再找已有 `.workflow`。
- **可以**在用户明确指定时，让项目根与源码目录重合。
- **可以**让项目根没有 Git；项目状态锚点和版本控制边界不是同一件事。

## 5. 无法判断时怎么问

只问一个定位问题，例如：

> 这个任务对应的项目根目录是哪一个？我会把 `.workflow` 放在该项目根下。

不要在得到答案前创建状态文件，也不要在源码目录中先建一份“临时状态”再迁移。
