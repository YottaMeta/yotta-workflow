# 元序路径模型

本文档解释 `SKILL.md`「〇、路径模型与状态目录判定」的实际用法，重点避免把项目根目录、源码目录和工作区根目录混为一谈。

## 1. 三个目录各管什么

| 名称 | 作用 | 判断要点 |
| --- | --- | --- |
| **项目根目录** | 单个项目的管理边界；状态、任务、决策、路线图和交接锚点都以它为锚点 | `.workflow\` 放这里；可以没有 Git |
| **源码目录** | 实际代码、资源或某个仓库所在位置 | 可以位于项目根下；`.git` 不代表它一定是项目根 |
| **工作区根目录** | 并列存放多个单独项目的父目录 | 它本身不是项目；不要在这里直接放 `.workflow` |

核心不变量：**状态跟着项目根走，不跟着源码仓库走。**

## 2. 定位算法

按顺序执行，前面有结果就不进入后面：

1. **用户指定优先**：用户直接给出了项目根，或交接锚点的“路径”指向项目根，直接使用。
2. **已有状态优先**：从当前工作目录向上逐级查找 `.workflow\STATE.md`；找到最近的一份就沿用，不迁移、不复制。
3. **无已有状态时分类**：
   - 当前目录是工作区根：先确定具体项目，再使用 `<工作区根>\<项目名>\.workflow\`；项目不明确时先问。
   - 当前目录位于源码仓库内，但上层有用户指定或明确的项目级边界：项目根取上层，源码目录只是项目内部目录。
   - 当前目录是单独项目的唯一边界，且没有上层项目边界：项目根可以与源码目录重合，状态放当前目录下。
   - 无法判断：先问，不猜，不在错误层级初始化。

## 3. 典型形态

### 形态 A：单仓库项目

```text
my-app\                 # 项目根 = 源码目录
├── .git\
├── .workflow\
├── src\
└── package.json
```

项目根和源码目录恰好重合，状态放 `my-app\.workflow\`。

### 形态 B：项目根下嵌套一个或多个源码仓库

```text
my-project\             # 项目根；.workflow 放这里
├── .workflow\
├── AGENTS.md            # 项目级说明
├── app\                 # 源码目录；可以有独立 .git
│   └── .git\
└── web\                 # 另一个源码目录；也可以有 .git
    └── .git\
```

`app` 或 `web` 里有 `.git`，只说明它们是版本控制仓库，不说明它们一定拥有整个项目。已有 `.workflow` 在上层时，状态始终留在项目根。

### 形态 C：工作区中并列多个项目

```text
D:\work\                # 工作区根；不要直接放 .workflow
├── project-a\          # 项目根
│   ├── .workflow\
│   └── src\
└── project-b\          # 另一个项目根
    ├── .workflow\
    └── app\
```

本次任务属于 `project-b` 时，使用 `D:\work\project-b\.workflow\`，不能因为 cwd 是 `D:\work` 就创建 `D:\work\.workflow\`。

### 形态 D：从源码子目录开始会话

```text
my-project\             # 项目根
├── .workflow\
└── app\                # 当前 cwd
    └── .git\
```

从 `app` 启动会话时，先向上找到 `my-project\.workflow\`，直接沿用；不要因为 `app` 有 `.git` 就在 `app` 再建一份状态。

## 4. 防误判清单

- **不要**仅凭 `.git` 认定项目根。
- **不要**仅凭 `package.json`、`src\` 或源码目录名认定项目根。
- **不要**在工作区根直接初始化 `.workflow`。
- **不要**把已有 `.workflow` 从项目根搬到源码目录。
- **不要**在多个 `.git` 仓库嵌套时随便选一个仓库根当项目根；先找已有 `.workflow`，再找明确的项目级边界。
- **可以**在单仓库、无上层项目边界时让项目根与源码目录重合。
- **可以**让项目根没有 Git；项目的管理边界和版本控制边界不是同一件事。

## 5. 无法判断时怎么问

只问一个定位问题，例如：

> 这个任务对应的项目根目录是哪一个？我会把 `.workflow` 放在该项目根下。

不要在得到答案前创建状态文件，也不要在源码目录中先建一份“临时状态”再迁移。
